# 放行评估稳定规则手册

本文件是放行判断的口径基准。所有规则由代码确定性执行,相同输入永远得到相同结论;
任何边界情形不依赖浮点 epsilon 的偶然性或调用时的偶然状态。

## 结论分级

- 段级:`CLEAR` / `CONDITIONAL` / `VIOLATION`
- 整体:`APPROVED` / `CONDITIONALLY_APPROVED` / `REJECTED`
  - 任一段 `VIOLATION` 或任务级违规(能力/资质)→ `REJECTED`
  - 无违规但存在 `CONDITIONAL` → `CONDITIONALLY_APPROVED`,附条件清单由条件理由派生
  - 全部 `CLEAR` → `APPROVED`

每次按序审查起飞、航路、悬停、备降四类段;备降段与航路段适用同一套空域/通告/能力规则,
不会因为是"备降"而漏审。

## 时间规则

1. 所有瞬时时间解析为 UTC 后比较;不带时区的输入按 Asia/Shanghai(固定 UTC+8)解释。
2. 所有时间窗口均为**半开区间 `[start, end)`**:
   - 段结束时刻 == 通告生效时刻 → 不冲突;
   - 段开始时刻 == 通告失效时刻 → 不冲突;
   - 边界时刻的归属因此完全确定。
3. 跨午夜不需要特判:绝对时间轴天然连续。每日重复窗口(`daily_windows`,如
   `22:00`–`06:00`)按本地日期展开成绝对区间再与段窗口求交;`end <= start` 时自动跨到次日。
4. 空域的绝对窗(`active_from`/`active_to`)与每日窗是**并集**;都未配置时视为恒有效。
   未配置 `effective_to` 的通告视为持续有效直到撤回。

## 空间规则

1. 多边形视为**闭集**:边界(含顶点、边)属于区域。航迹与禁飞区边界**相切、压线、
   擦过顶点一律判冲突**——宁可保守也不漏判。
2. 判定先显式检测接触、再做穿越判定,不依赖 epsilon 的偶然性;退化几何(零长度段)
   按点处理,不会误判为"接触一切"。
3. 洞(内环)的内部不属于区域;洞的边界属于区域(对禁飞区取保守方向)。
4. 垂直方向为**闭区间**:段高度恰好等于空域下限或上限都算冲突。
5. 距离不足缓冲带(默认 500m,可由规则参数调整)时产生 `AIRSPACE_BUFFER`/`NOTICE_BUFFER`
   条件级理由,派生"保持间隔"类附条件。

## 版本与撤回规则

1. 空域、通告按 `(id, version)` 不可变存储;新版本必须等于当前最大版本 +1,
   同版本同内容重发幂等返回,同版本不同内容返回 409。
2. 评估只采用每个 `notice_id` 的**最新未撤回版本**;撤回是追加事件
   (`notice_withdrawals`),不改写通告历史版本。
3. 撤回对**后续评估**立即生效;**历史决定不变**——其快照仍记录当时引用的通告版本。
   系统为引用过该通告的决定生成 `notice_withdrawn` 提醒,提示可提交新计划版本重新评估。
4. 已撤回的通告不能发新版本;重复撤回返回 409。
5. 生效前被撤回的通告,其到点任务只留审计记录,不产生复核任务。

## 新通告影响已放行计划

1. 通告发布时登记 `notice_effective` 定时工作,到点(发布即生效则立即)扫描
   当前有效的 `APPROVED`/`CONDITIONALLY_APPROVED` 决定。
2. 扫描只生成**待复核任务**(`review_tasks`,状态 pending)与**提醒**(`reminders`),
   **绝不改写原决定**;同一 `(decision, notice, version)` 只生成一次(唯一约束保证幂等)。
3. 复核结论由人工通过新计划版本(产生新决定,`revision_of` 链回旧决定)表达,
   复核任务本身走 pending → acknowledged → resolved 流程。

## 并发规则

1. 同一任务的并发提交只产生**一个有效版本**:`(mission_id, plan_version)` 主键 +
   `idempotency_key` 唯一约束,版本分配与插入在同一事务内完成,败者收到 409。
2. 相同幂等键重复提交(含并发)是**幂等重放**:返回首次提交的决定,不产生新版本。
3. 幂等键被其他任务占用返回 409。
4. 显式版本链:默认要求 `expected_base_version` 等于当前版本(新任务为 0),
   基于过期版本的提交返回 409;通过则产生新版本并链接 `revision_of`。

## 持久化与恢复

1. 所有状态存于 SQLite(由运行时配置指定路径,缺省为内存库);决定不可变,
   快照固化当时采用的空域、通告、规则参数、机型、资质与人工意见。
2. 定时工作(`scheduled_jobs`)持久化:重启后 `recover()` 立即补跑到期任务,
   调度线程继续后续周期,因此"重启后仍能继续定时生效工作"。
3. 未完成的复核任务本就持久化在库中,值班人员重启后通过 `GET /reviews` 继续处理。
4. 全部状态变化写入 `audit_events`;`GET /decisions/{id}/trace` 从任一结论
   追溯完整判断过程(决定、分段理由、快照、人工意见、审计链、关联复核)。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | 进程存活(不代表业务完成) |
| PUT/GET | `/zones/{id}`、`/zones` | 空域版本化登记与查询 |
| PUT/GET/POST | `/notices/{id}`、`/notices`、`/notices/{id}/withdraw` | 通告版本化登记、查询、撤回 |
| PUT/GET | `/aircraft-models/{id}`、`/operators/{id}` | 机型能力与操作员资质(当前值,快照固化历史) |
| PUT | `/rulesets/{version}` | 规则参数版本化 |
| POST/GET | `/missions`、`/missions/{id}` | 提交任务(同步评估)与查询 |
| GET | `/decisions/{id}`、`/decisions/{id}/trace` | 决定与完整追溯 |
| POST | `/decisions/{id}/annotations` | 追加人工意见(不回写决定) |
| GET/POST | `/reviews`、`/reviews/{id}/ack`、`/reviews/{id}/resolve` | 待复核清单与流转 |
| GET | `/reminders` | 提醒列表 |
| POST | `/jobs/run-due` | 手动触发到期的定时工作(运维/演示用) |

错误统一为 `{"error": {"code", "message"}}`,状态码语义:400 请求体非法、
404 不存在、409 版本/状态冲突、422 内容不合法、500 内部错误。
